# The P620 catalogue — bench-model, 2026-10-12

The RTX 3090 moved from jarvis into the P620 (Threadripper PRO 3975WX, 61 GB RAM), and
llama-swap moved with it, trimmed to the ten ids whose weights sit entirely in VRAM.
Every id was re-measured so the `bin/model` speed column describes the box it runs on.

Method: `bin/bench-model <id> 3` run on the P620 against llama-swap on `127.0.0.1:8000`;
generation tok/s is the median of three 300-token runs from llama.cpp `timings`,
temperature 0.6; prefill is one ~12k-token prompt that differs every run. VRAM is the
whole card while the model was loaded (`--fit` sizes context to fill it).

## What changed

**The MTP quants gained 8-16%** (gsq-rco 68 -> 73, heretic 65 -> 71, turbo 52 -> 60) while
every non-speculative model is within noise of its jarvis number. Same card; llama.cpp
was rebuilt on the P620 (`build-3090`, `-march=native`). The likely reason is the host: the
draft/verify loop does more CPU-side work per token than plain decoding, and the
Threadripper turns it around faster. Not isolated further.

**`eco` is not the coder's twin any more.** It serves the same weights, but its llama-swap
entry adds server-side sampling (`--repeat-penalty 1.05`, top-k/top-p/min-p) and prompt-cache
options, and generation is ~16% slower (135 vs 161) — most likely the repeat penalty, which
is applied on every token. The old row simply copied the coder's 162.

Not in the table: the Flash-Next `q38-*` ladder and `dsv4-q8` need RAM offload far beyond
what the 3090 setup was trimmed for, so they were dropped from llama-swap with the move.
